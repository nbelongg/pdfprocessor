# Detailed Analysis: Jobs Stuck in Pending Status

After analyzing your codebase, I've identified **several critical issues** that can cause jobs to get stuck in `pending` status. Here's a comprehensive breakdown:

## 🔴 Critical Issue #1: Missing Queue Specification in Worker Command

**Location:** `.replit` line 45

```python
args = "celery -A celeryconfig worker --loglevel=info --concurrency=3"
```

**Problem:** The worker is **NOT listening to any specific queues**. By default, Celery workers only listen to the `celery` queue (the default queue), but your tasks are being routed to specific queues:

- `process_batch_task` → `batch_processing` queue (line 632 of `page_modules/job_queue.py`)
- `process_pdf_task` → `pdf_processing` queue

**Result:** Tasks are sent to `batch_processing` queue, but worker is listening to `celery` queue. **Tasks never get picked up.**

**Fix Required:**
```bash
celery -A celeryconfig worker --loglevel=info --concurrency=3 -Q batch_processing,pdf_processing,metadata_updates
```

## 🟡 Issue #2: No Automatic Status Update When Task Starts

**Location:** `tasks.py` lines 425-438

```python
try:
    logger.info(f"Starting batch task...")
    
    # Status update to 'running' happens HERE
    if not preview_mode:
        try:
            update_celery_job_status(job_id, 'running', ...)
```

**Problems:**

1. **Status update happens INSIDE the task function** - If the task fails before reaching line 428 (e.g., during deserialization, imports, or parameter validation), the status never updates from `pending`.

2. **Import happens inside function** (line 419) - If there's an import error, the status update function is never even imported.

3. **No Celery signal handlers** - Celery has built-in signals (`task_prerun`, `task_failure`) that fire when tasks start/fail, but your code doesn't use them.

**Scenarios where status stays `pending`:**
- Task deserialization fails (bad JSON, incompatible types)
- Import error in `tasks.py`
- Exception raised before line 428
- Worker crashes before task starts
- Database connection fails during status update (line 428)

## 🟡 Issue #3: No Fallback Status Tracking

**Location:** `celeryconfig.py` - Missing signal handlers

Your code maintains a custom `celery_jobs` table, but it has **no automatic synchronization** with Celery's built-in task states. Celery tracks task states (`PENDING`, `STARTED`, `RETRY`, `FAILURE`, `SUCCESS`) in Redis, but your database table is only updated manually.

**Problems:**
- If status update fails (line 428-438), there's no fallback
- No visibility into why a task is stuck
- Can't distinguish between "worker hasn't picked up task" vs "task started but status update failed"

## 🟢 Issue #4: Worker Configuration Mismatch

**Location:** `celeryconfig.py` lines 162, 165

```python
task_acks_late=True,  # Line 162
worker_prefetch_multiplier=1,  # Line 165
```

**Analysis:** These settings are actually GOOD for your use case:
- `task_acks_late=True` - Worker only acknowledges task AFTER completion (prevents message loss)
- `worker_prefetch_multiplier=1` - Worker only fetches 1 task at a time (good for long-running tasks)

However, combined with Issue #1 (wrong queue), these settings mean:
- Worker prefetches 1 task from `celery` queue
- Your tasks go to `batch_processing` queue
- Worker never sees them, **permanently stuck**

### 2. **Add Celery Signal Handlers** (Issues #2, #3)
Add to `celeryconfig.py`:
```python
from celery import signals

@signals.task_prerun.connect
def task_prerun_handler(sender=None, task_id=None, **kwargs):
    """Update status to 'running' when task starts."""
    from utils.db.jobs import update_celery_job_status, get_celery_job
    job = get_celery_job(task_id)
    if job and job['status'] == 'pending':
        update_celery_job_status(task_id, 'running', progress_message='Task started')

@signals.task_failure.connect  
def task_failure_handler(sender=None, task_id=None, exception=None, **kwargs):
    """Update status to 'failed' when task fails."""
    from utils.db.jobs import update_celery_job_status
    update_celery_job_status(task_id, 'failed', error_message=str(exception))
```
**Impact:** Ensures status updates even if task fails before executing its first line.
