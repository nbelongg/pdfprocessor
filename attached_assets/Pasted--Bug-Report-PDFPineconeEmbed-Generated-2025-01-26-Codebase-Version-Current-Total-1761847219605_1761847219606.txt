## Critical Bugs 🔴

### Bug #1: Blocking Call Without Timeout - Can Deadlock System

**Severity:** Critical  
**Location:** `tasks.py:428`  
**Impact:** High - Can cause batch processing jobs to hang indefinitely

#### Description
The `process_batch_task` function calls `pdf_result.get()` without a timeout parameter. If any individual PDF processing task hangs or never completes, the entire batch processor will block indefinitely waiting for that result.

#### Current Code
```python
# tasks.py:419-428
pdf_result = process_pdf_task.apply_async(args=[
    file_id,
    row_metadata.get('filename', f'file_{file_id}.pdf'),
    row_metadata,
    product_config,
    job_id,
    namespace
])

pdf_result_data = pdf_result.get()  # ❌ No timeout - can block forever
```

#### Recommended Fix
```python
pdf_result = process_pdf_task.apply_async(args=[...])

try:
    # Add timeout to prevent indefinite blocking
    pdf_result_data = pdf_result.get(timeout=3600)  # 1 hour timeout
except Exception as e:
    logger.error(f"Task {file_id} timed out or failed: {e}")
    pdf_result_data = {
        'status': 'error',
        'file_id': file_id,
        'error': f"Task execution failed: {str(e)}"
    }
```

#### Additional Impact
This bug affects the entire batch processing pipeline. If processing 100 PDFs and PDF #5 hangs, all subsequent PDFs will wait indefinitely.

#### Description


### Bug #3: Synchronous Processing Bottleneck - Negates Async Benefits

**Severity:** Critical  
**Location:** `tasks.py:419-428`  
**Impact:** Medium - Reduces throughput significantly for batch processing

#### Description
The `process_batch_task` submits tasks asynchronously using `apply_async()`, but then immediately calls `.get()` on each result, blocking until completion. This means all PDFs are processed sequentially instead of in parallel, defeating the purpose of using Celery async tasks.

#### Current Code
```python
# tasks.py:385-428
for idx, row_idx in enumerate(selected_indices):
    # ... setup code ...
    
    pdf_result = process_pdf_task.apply_async(args=[...])  # ✅ Async submission
    
    pdf_result_data = pdf_result.get()  # ❌ Immediately blocks - no parallelism!
    
    results['details'].append(pdf_result_data)
```

#### Recommended Fix
```python
# Collect all async tasks first
async_tasks = []
for idx, row_idx in enumerate(selected_indices):
    # ... setup code ...
    
    pdf_result = process_pdf_task.apply_async(args=[
        file_id,
        row_metadata.get('filename', f'file_{file_id}.pdf'),
        row_metadata,
        product_config,
        job_id,
        namespace
    ])
    
    async_tasks.append({
        'task': pdf_result,
        'file_id': file_id,
        'row_idx': row_idx,
        'index': idx
    })

# Process results as they complete (can use as_completed for parallel processing)
from celery.result import AsyncResult
import time

completed = 0
while completed < len(async_tasks):
    for task_info in async_tasks:
        task = task_info['task']
        
        if task.ready():
            try:
                pdf_result_data = task.get(timeout=10)  # Small timeout since ready
                results['details'].append(pdf_result_data)
                
                if pdf_result_data['status'] == 'success':
                    results['total_pdfs'] += 1
                    results['total_chunks'] += pdf_result_data.get('chunks', 0)
                    results['vectors_stored'] += pdf_result_data.get('vectors_uploaded', 0)
                
                completed += 1
                
                # Update progress
                self.update_progress(
                    completed,
                    len(async_tasks),
                    f"Processed {completed}/{len(async_tasks)} PDFs..."
                )
            except Exception as e:
                logger.error(f"Error getting result for {task_info['file_id']}: {e}")
                results['details'].append({
                    'file_id': task_info['file_id'],
                    'status': 'error',
                    'error': str(e)
                })
                completed += 1
    
    time.sleep(0.1)  # Small delay to avoid busy waiting
```

#### Performance Impact
- **Current:** 10 PDFs × 5 minutes each = 50 minutes total (sequential)
- **Fixed:** 10 PDFs processed in parallel = ~5-10 minutes total (depending on worker count)

### Bug #6: Database Connection Leak Pattern

**Severity:** High  
**Locations:**
- `utils/db/jobs.py:86-105` - `get_job_history()`
- `utils/db/jobs.py:161-176` - `get_job_chunks()`

- `utils/db/jobs.py:336-362` - `get_all_celery_jobs()`
- `utils/db/documents.py:68-79` - `get_parsed_document()`
- Multiple other read functions

**Impact:** High - Can exhaust database connection pool

#### Description
Several read functions use manual connection management with `try/finally` blocks instead of context managers. While `finally` ensures cleanup, if an exception occurs during cursor operations or if `conn.close()` itself fails, connections may leak. Additionally, these functions don't use the standardized connection management utilities.

#### Current Code
```python
# utils/db/jobs.py:86-105
def get_job_history(limit: int = 50) -> List[Dict[str, Any]]:
    """Get processing job history."""
    conn = get_db_connection()
    try:
        with conn.cursor() as cur:
            cur.execute(...)
            return [dict(row) for row in cur.fetchall()]
    finally:
        conn.close()  # ⚠️ Manual cleanup - can fail
```

#### Recommended Fix
```python
def get_job_history(limit: int = 50) -> List[Dict[str, Any]]:
    """Get processing job history."""
    with get_db_connection() as conn:  # ✅ Automatic cleanup
        with conn.cursor() as cur:
            cur.execute(
                """
                SELECT job_id, status, sheet_url, sheet_tab,
                       total_pdfs, processed_pdfs, total_chunks,
                       total_embeddings, vectors_stored,
                       created_at, completed_at
                FROM processing_jobs
                ORDER BY created_at DESC
                LIMIT %s
                """,
                (limit,)
            )
            return [dict(row) for row in cur.fetchall()]
```

#### Note

```python
from utils.exceptions import TransientError

def initialize_pinecone(config: Dict):
    """Initialize Pinecone client and ensure index exists."""
    try:
        api_key = config.get('pinecone_api_key')
        if not api_key:
            raise ValueError("pinecone_api_key missing from config")
        
        try:
            pc = Pinecone(api_key=api_key)
        except Exception as e:
            raise ValueError(f"Failed to initialize Pinecone client: {e}") from e
        
        index_name = config.get('index_name', 'research-papers')
        dimension = config.get('embedding_dimension', 1536)
        
        try:
            existing_indexes = pc.list_indexes()
        except Exception as e:
            raise TransientError(f"Failed to list Pinecone indexes: {e}") from e
        
        index_exists = False
        for index_info in existing_indexes:
            if hasattr(index_info, 'name') and index_info.name == index_name:
                index_exists = True
                break
            elif isinstance(index_info, dict) and index_info.get('name') == index_name:
                index_exists = True
                break
        
        if not index_exists:
            try:
                pc.create_index(
                    name=index_name,
                    dimension=dimension,
                    metric='cosine',
                    spec=ServerlessSpec(cloud='aws', region='us-east-1')
                )
                time.sleep(1)
            except Exception as e:
                raise TransientError(f"Failed to create Pinecone index: {e}") from e
        
        try:
            index = pc.Index(index_name)
            return index
        except Exception as e:
            raise TransientError(f"Failed to get Pinecone index: {e}") from e
            
    except (TransientError, ValueError):
        raise
    except Exception as e:
        raise ValueError(f"Unexpected error initializing Pinecone: {e}") from e

def upload_to_pinecone(...):
    """Upload embeddings to Pinecone."""
    # ... existing vector preparation ...
    
    batch_size = 100
    total_uploaded = 0
    
    for i in range(0, len(vectors), batch_size):
        batch = vectors[i:i + batch_size]
        try:
            index.upsert(vectors=batch, namespace=namespace)
            total_uploaded += len(batch)
        except Exception as e:
            logger.error(f"Failed to upload batch {i}:{i+batch_size} to Pinecone: {e}")
            # Check if it's a transient error (rate limit, network)
            error_str = str(e).lower()
            if any(keyword in error_str for keyword in ['rate limit', 'timeout', 'connection', 'network']):
                raise TransientError(f"Pinecone upload failed (transient): {e}") from e
            else:
                raise ValueError(f"Pinecone upload failed: {e}") from e
    
    return total_uploaded
```

### Bug #9: Race Condition in File Lock Cleanup

**Severity:** Medium  
**Location:** `scheduler.py:232-236`  
**Impact:** Low - Rare edge case

#### Description
The file lock cleanup in the `scheduler_lock` context manager checks if the file exists, then deletes it. Between the check and deletion, another process could create the lock file, leading to a potential race condition.

#### Current Code
```python
# scheduler.py:232-236
elif lock_acquired:
    lock_file = f"/tmp/scheduler_lock_{job_id}.lock"
    if os.path.exists(lock_file):  # ⚠️ Check
        os.remove(lock_file)        # ⚠️ Delete - race condition window
    logger.info(f"Released file lock for job {job_id}")
```

#### Recommended Fix
```python
elif lock_acquired:
    lock_file = f"/tmp/scheduler_lock_{job_id}.lock"
    try:
        os.remove(lock_file)  # Will raise FileNotFoundError if already deleted
    except FileNotFoundError:
        # Already removed by another process or cleanup
        pass
    except Exception as e:
        logger.warning(f"Failed to remove lock file {lock_file}: {e}")
    logger.info(f"Released file lock for job {job_id}")
```

#### Better Solution
Use proper file locking library:
```python
import fcntl

@contextmanager
def scheduler_lock(job_id: int, timeout: int = SCHEDULER_LOCK_TIMEOUT):
    lock_file = f"/tmp/scheduler_lock_{job_id}.lock"
    
    try:
        f = open(lock_file, 'w')
        try:
            fcntl.flock(f, fcntl.LOCK_EX | fcntl.LOCK_NB)
            f.write(str(os.getpid()))
            f.flush()
            yield
        finally:
            fcntl.flock(f, fcntl.LOCK_UN)
            f.close()
            try:
                os.remove(lock_file)
            except FileNotFoundError:
                pass
    except BlockingIOError:
        raise RuntimeError(f"Job {job_id} is already running")
```

```python
def update_progress(self, current: int, total: int, message: str) -> None:
    """
    Update task progress.
    
    Args:
        current: Current progress value
        total: Total progress value (must be > 0)
        message: Progress message to display
    """
    if total <= 0:
        logger.warning(f"Invalid progress total: {total}, using 0%")
        percent = 0
    else:
        percent = min(100, max(0, int((current / total) * 100)))
    
    self.update_state(
        state='PROGRESS',
        meta={
            'current': current,
            'total': total,
            'message': message,
```
